# 한국어 코드 설명 주석

## 목적

사용자가 지정한 코드 파일에 한국어 설명 주석을 추가한다. 설명은 코딩 초보자에게 맞추고 코드의 실행 결과와 기존 기능을 유지한다.

## 파일 확인

- 경로가 없으면 설명할 파일 경로를 요청한다. 상대 경로는 현재 프로젝트 루트를 기준으로 해석한다.
- 대상 파일 전체와 적용되는 `AGENTS.md`를 읽는다. 동작 이해에 필요한 import, 호출부, 타입 정의만 추가로 확인한다.
- 경로가 없거나 여러 파일로 해석되면 정확한 대상을 질문한다. 프로젝트 밖의 파일은 경로가 명확하게 지정된 경우에만 다룬다.
- 기존 변경 사항과 주석을 보존한다. 대상 이외의 파일은 동작 파악을 위해 읽되, 요청 없이 수정하지 않는다.

## 확인이 필요한 내용

- 코드에서 직접 확인되는 사실과 작성자의 의도, 서비스 정책을 구분한다.
- 계산 과정은 설명할 수 있어도 특정 숫자를 선택한 이유가 확인되지 않으면 이유를 만들어 넣지 않는다.
- 코드와 요구사항이 충돌하거나 외부 함수의 동작을 확인할 수 없으면 해당 부분에 대한 질문을 짧고 구체적으로 한다.
- 답변이 필요한 주석은 보류하고, 독립적으로 확인 가능한 부분은 진행한다. 답변 전에는 추측성 설명이나 가상의 정책을 주석으로 저장하지 않는다.
- 버그가 보여도 이 작업에서 임의로 고치지 않는다. 실제 동작을 설명하고 문제는 사용자에게 별도로 알린다.

## 주석 작성

- 파일의 역할을 간단히 설명하고, 어려운 함수나 로직에는 입력, 처리 과정, 반환값을 필요한 만큼 설명한다.
- 모든 줄을 번역하듯 주석을 달지 않는다. 조건 분기, 비동기 처리, 상태 변경, 데이터 변환처럼 이해가 필요한 곳에 집중한다.
- 문법의 이름보다 이 코드가 하는 일을 먼저 설명한다. 전문 용어가 필요하면 짧은 한국어 풀이를 붙인다.
- 설명은 바로 위나 가까운 위치에 두고, 기존 주석이 충분하면 중복하지 않는다.
- TypeScript와 JavaScript에는 `//` 또는 `/** ... */`, JSX에는 `{/* ... */}`, CSS에는 `/* ... */`처럼 해당 위치에 맞는 주석 문법을 사용한다.
- 주석을 지원하지 않는 JSON 같은 파일은 강제로 주석을 삽입하지 않는다. 원본을 확인한 뒤 별도 설명 문서 방식이 괜찮은지 질문한다.
- `"use client"`, `"use server"`, shebang, 라이선스, 도구 지시 주석의 위치와 의미를 보존한다. `@ts-ignore`, `eslint-disable`, 번들러 지시 같은 동작에 영향을 주는 주석을 추가하지 않는다.
- 로직, 식별자, 타입, 문자열, 의존성을 변경하거나 파일 전체를 재정렬하지 않는다. JSX에서는 주석 때문에 렌더링되는 공백이나 텍스트가 바뀌지 않도록 한다.

예시:

```ts
// 참석한다고 답한 사람만 합산합니다.
// 각 응답에서 본인 1명과 함께 오는 사람 수를 더합니다.
const totalGuests = responses
  .filter((response) => response.attendance === "attending")
  .reduce((total, response) => total + 1 + response.companionCount, 0);
```

## 검증과 전달

- 수정 전후 diff를 확인해 설명 주석 외에 기능이나 값이 바뀌지 않았는지 검토한다.
- 프로젝트에 설정된 관련 검사 명령으로 문법 오류를 확인한다. 주석 작업만을 위해 의존성을 새로 설치하지 않는다.
- 완료 시 수정한 파일 링크, 설명을 추가한 핵심 부분, 검사 결과를 간단히 알려준다. 아직 답변이 필요한 부분은 명시한다.
- 커밋이나 푸시는 별도 요청 또는 이 작업에 대한 명확한 사전 지시가 있을 때만 한다.
